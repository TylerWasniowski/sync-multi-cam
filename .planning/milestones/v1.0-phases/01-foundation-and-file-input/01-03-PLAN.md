<task type="auto">
  <name>Task 1: Create FFmpeg WASM lazy loader and status indicator component</name>
  <files>src/lib/ffmpeg.ts, src/components/FFmpegStatus.tsx</files>
  <action>
1. Create `src/lib/ffmpeg.ts` following research Pattern 1 (Lazy FFmpeg Loading with SharedArrayBuffer Detection):
   ```typescript
   import { FFmpeg } from '@ffmpeg/ffmpeg';
   import { toBlobURL } from '@ffmpeg/util';
   import { FFMPEG_CORE_VERSION, FFMPEG_CDN_BASE } from './constants';
   ```

   Implement:
   - `isMultiThreadSupported(): boolean` -- returns `typeof SharedArrayBuffer !== 'undefined'`
   - `getFFmpegMode(): 'multi-thread' | 'single-thread'` -- returns mode based on SharedArrayBuffer availability
   - `getFFmpeg(): Promise<FFmpeg>` -- singleton pattern:
     - If `ffmpegInstance` already exists, return it immediately
     - Create `new FFmpeg()`
     - Detect multi-thread support
     - Build CDN base URL: `${FFMPEG_CDN_BASE}/@ffmpeg/${isMultiThread ? 'core-mt' : 'core'}@${FFMPEG_CORE_VERSION}/dist/esm`
     - Use `toBlobURL()` to fetch coreURL (text/javascript) and wasmURL (application/wasm)
     - If multi-thread, also fetch workerURL (text/javascript) via toBlobURL
     - Call `ffmpeg.load()` with the config object
     - Store in `ffmpegInstance` singleton and return
     - Add `ffmpeg.on('log', ...)` handler that logs to console (useful for debugging in later phases)

   Important: Do NOT catch errors in getFFmpeg -- let them propagate to the caller so the UI can display appropriate error states.

2. Create `src/components/FFmpegStatus.tsx`:
   - Props: `status: 'idle' | 'loading' | 'ready' | 'error'`, `error?: string`
   - Render based on status:
     - `idle`: Nothing rendered (return null)
     - `loading`: A subtle indicator with a spinner/pulse animation: "Initializing FFmpeg..." in `text-gray-400 text-sm` with a small animated dot or spinner (use Tailwind `animate-pulse` or a simple CSS animation)
     - `ready`: A green checkmark + "FFmpeg ready" + thread mode indicator ("multi-thread" or "single-thread") in `text-green-400 text-sm`
     - `error`: A red warning + error message in `text-red-400 text-sm`
   - Keep this component simple -- it is purely presentational
  </action>
