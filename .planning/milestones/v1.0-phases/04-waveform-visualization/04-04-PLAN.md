BUG 1 (PRIMARY) - Wrong endBucket in WaveformCanvas.tsx line 73:
  CURRENT:  endBucket = Math.min(startBucket + width, peaks.length)
  CORRECT:  endBucket = Math.min(Math.ceil((scrollOffset + width * samplesPerPixel) / peaks.samplesPerBucket), peaks.length)
  WHY: `startBucket + width` adds pixel count to bucket index -- unit mismatch.
  The viewport spans `width * samplesPerPixel` samples = `width * SPP / SPB` buckets.

BUG 2 (SECONDARY) - Hardcoded 1px rect width in WaveformCanvas.tsx line 101:
  CURRENT:  ctx.rect(x, yTop, 1, barHeight)
  CORRECT:  ctx.rect(x, yTop, Math.max(1, Math.ceil(peaks.samplesPerBucket / samplesPerPixel)), barHeight)
  WHY: When bucket spacing is fractional, 1px rects leave gaps creating striped artifacts.

BUG 3 (TERTIARY) - Integer truncation in waveformPeaks.ts line 67:
  CURRENT:  samplesPerBucket: Math.floor(samples.length / min.length)
  CORRECT:  samplesPerBucket: samples.length / min.length
  WHY: Math.floor drops fractional part, causing progressive positional drift.
  Example: 195000 samples / 100000 buckets = actual 1.95, stored as 1.
  By bucket 99999: position drift = 95000 samples.

  <action>
  Fix the two rendering bugs in the main draw useEffect of WaveformCanvas.tsx:

  1. **Fix endBucket calculation (line 73):**
     Replace:
     ```typescript
     const endBucket = Math.min(startBucket + width, peaks.length);
     ```
     With:
     ```typescript
     const endBucket = Math.min(
       Math.ceil((scrollOffset + width * samplesPerPixel) / peaks.samplesPerBucket),
       peaks.length
     );
     ```
     This correctly converts the viewport's sample range into bucket count. The viewport spans `width * samplesPerPixel` samples starting from `scrollOffset`, which covers `(scrollOffset + width * SPP) / SPB` buckets total from the start.

  2. **Fix rect width (line 101):**
     Replace:
     ```typescript
     ctx.rect(x, yTop, 1, barHeight);
     ```
     With:
     ```typescript
     const barWidth = Math.max(1, Math.ceil(peaks.samplesPerBucket / samplesPerPixel));
     ctx.rect(x, yTop, barWidth, barHeight);
     ```
     Move the `barWidth` computation OUTSIDE the for loop (before `ctx.beginPath()`) since it's constant for all buckets in a given frame. The value represents how many pixels each bucket should span. When buckets are smaller than pixels (detail level zoomed out), bars are 1px. When buckets are larger than pixels (overview zoomed in), bars scale to fill correctly.

     Updated loop structure:
     ```typescript
     // Draw waveform
     ctx.fillStyle = WAVEFORM_COLOR;
     const barWidth = Math.max(1, Math.ceil(peaks.samplesPerBucket / samplesPerPixel));
     ctx.beginPath();
     for (let i = startBucket; i < endBucket; i++) {
       const x = (i * peaks.samplesPerBucket - scrollOffset) / samplesPerPixel;
       if (x < -barWidth || x > width + 1) continue;
       const minVal = peaks.min[i];
       const maxVal = peaks.max[i];
       const yTop = halfHeight - maxVal * halfHeight;
       const yBottom = halfHeight - minVal * halfHeight;
       const barHeight = Math.max(1, yBottom - yTop);
       ctx.rect(x, yTop, barWidth, barHeight);
     }
     ctx.fill();
     ```
     Note: Also update the visibility cull check from `x < -1` to `x < -barWidth` to avoid culling wide bars that partially overlap the viewport edge.

  These two fixes together resolve both the clipping (endBucket draws enough buckets) and blockiness (rect width fills pixel gaps between buckets).
