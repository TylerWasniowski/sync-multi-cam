Replace the hardcoded `176` offset with a dynamically measured label offset. The current layout after v2.1 has: mute button outside the dimmed container, w-32 label (not w-40), and px-4 padding on both the panel and track wrapper divs. The hardcoded 176 no longer matches reality.

**Implementation approach:**

1. Add a ref to measure the actual non-canvas offset. Use a `labelOffsetRef` (useRef<number>(176)) that gets updated when the first `[data-waveform-canvas]` element is measured. Specifically: after the panel's ResizeObserver fires and `panelWidth` is known, query for the first `[data-waveform-canvas]` element inside the panel, get its `getBoundingClientRect().left`, subtract the panel's `getBoundingClientRect().left`, and store this as the label offset.

2. Replace all 4 occurrences of the hardcoded `176` with the dynamic `labelOffset` value:
   - Line 61: `const canvasWidth = Math.max(panelWidth - labelOffset, 200);`
   - Line 141 (handleWheel): `const offsetX = e.clientX - rect.left - labelOffset;`
   - Line 218 (panelPointerToTime): `const offsetX = e.clientX - rect.left - labelOffset;`
   - Line 269 (handlePanelPointerMove hover): `const offsetX = e.clientX - rect.left - labelOffset;`

3. Update the measurement in a useEffect that depends on `panelWidth` and `trackEntries.length` (so it re-measures when tracks appear or panel resizes). The measurement logic:
   ```typescript
   useEffect(() => {
     const el = panelRef.current;
     if (!el || trackEntries.length === 0) return;
     const canvas = el.querySelector('[data-waveform-canvas]');
     if (!canvas) return;
     const panelRect = el.getBoundingClientRect();
     const canvasRect = canvas.getBoundingClientRect();
     labelOffsetRef.current = canvasRect.left - panelRect.left;
   }, [panelWidth, trackEntries.length]);
   ```

4. Create a derived `labelOffset` constant from the ref for use in computations:
   ```typescript
   const labelOffset = labelOffsetRef.current;
   ```
   Place this AFTER the measurement effect and BEFORE `canvasWidth` computation. Since the ref updates trigger no re-render on its own, and the values are used in callbacks that close over stale state, use a state variable instead of a ref if the initial render needs to be correct. However, since the measurement happens after layout and the callbacks will read the ref at call time, a ref is sufficient -- the only concern is `canvasWidth` which is used in render. Use a state variable `labelOffset` with setState so `canvasWidth` re-derives correctly:

   Replace the ref approach with:
   ```typescript
   const [labelOffset, setLabelOffset] = useState(176); // fallback to 176 until measured
   ```
   And the effect calls `setLabelOffset(canvasRect.left - panelRect.left)`.

5. Remove the outdated comments referencing "w-40" and "176px". Add a comment: `// Dynamically measured: distance from panel left edge to first canvas container`.

**What NOT to change:** Do NOT touch WaveformTrack.tsx or WaveformCanvas.tsx -- their math is already correct since they use their own element rects.

<task type="auto">
  <name>Task 2: Fix play-from-beginning bug (PLAY-02)</name>
  <files>src/components/PlaybackSection.tsx, src/lib/videoSync.ts</files>
  <action>
Fix two related issues that cause playback to start from time 0 instead of the expected position.

**Root cause:** In `PlaybackSection.tsx`, the `allVideosReady` effect (line 148) creates the timeline clock via `createTimelineClock()`. The engine's internal `currentTime` starts at 0 (videoSync.ts line 39). The effect sets each video's `.currentTime` to the correct local time and calls `setCurrentTime(maxOffset)` for React state, but it NEVER calls `engine.seek(maxOffset)`. So the engine's internal clock is at 0, while the UI shows maxOffset. When the user presses Play, `engine.start()` begins from `clockStartTime = currentTime = 0`.

**Fix in PlaybackSection.tsx:**

After the engine is created (after line 194 `syncEngineRef.current = engine;`), add:
```typescript
engine.seek(maxOffset);
```

This synchronizes the engine's internal `currentTime` with the React state. The videos are already positioned at maxOffset by the loop above, and `engine.seek()` will redundantly set them again (harmless), but critically it sets the engine's `currentTime` to `maxOffset`.

**Additionally**, verify the "play from cursor" flow is correct:
- When user scrubs/seeks, `handleScrubSeek` calls `engine.seek(seekTime)` which sets engine's `currentTime` -- this path is already correct.
- When user uses TransportBar seek slider, `handleSeek` calls `engine.seek(seekTime)` -- also correct.
- After pausing, `engine.stop()` preserves the engine's `currentTime` (it just sets `active = false`). When `engine.start()` is called, `clockStartTime = currentTime` which is the paused position -- correct.

So the only fix needed is adding `engine.seek(maxOffset)` after engine creation.

**No changes needed to videoSync.ts** -- the engine's `seek()` method already correctly sets `currentTime`. The bug is purely that `seek()` was never called after creation to set the initial position.

**What NOT to change:** Do NOT modify handlePlay, handlePause, handleSeek, handleScrubSeek, or any other interaction handlers. Do NOT change the engine's constructor to accept an initial time parameter (that would be over-engineering -- `seek()` after creation is the established pattern). Do NOT change end-of-playback behavior (per user decision).
