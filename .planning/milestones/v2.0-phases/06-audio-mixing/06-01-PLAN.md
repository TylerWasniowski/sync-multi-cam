**2. Create src/lib/audioMixer.ts:**

Create the audio mixer factory module following the established project pattern (factory function returning an interface object, same as `createSyncEngine` in videoSync.ts and `createPosterExtractor` in posterFrame.ts).

The module exports:

```typescript
export type { AudioMode } from '../types/index.ts';  // re-export for convenience

export interface AudioMixer {
  setMode: (mode: AudioMode) => void;
  destroy: () => void;
}

export function createAudioMixer(videoElements: HTMLVideoElement[]): AudioMixer;
```

Implementation details for `createAudioMixer`:

- Create a new `AudioContext`
- For each video element, call `audioCtx.createMediaElementSource(video)` to capture its audio into the Web Audio graph
- For each source, create a `GainNode` via `audioCtx.createGain()`
- Wire: source -> gain -> audioCtx.destination (for each video)
- Initialize all gain values to `1 / videoElements.length` (all-mix mode, prevents clipping)
- `setMode(mode)`:
  - If `audioCtx.state === 'suspended'`, call `audioCtx.resume()` (handles tab background and autoplay policy)
  - Get `audioCtx.currentTime` as the scheduling anchor
  - Use `FADE_TIME_CONSTANT = 0.015` (exponential decay, 95% in ~45ms)
  - If mode is `'all'`: set each gain to `1 / gainNodes.length` via `gain.gain.setTargetAtTime(level, now, FADE_TIME_CONSTANT)`
  - If mode is a number: set that index's gain to `1.0` and all others to `0` via `setTargetAtTime()`
  - Do NOT use direct `gain.value` assignment (causes audible clicks -- see research anti-patterns)
  - Do NOT disconnect/reconnect nodes (permanently silences audio -- see research anti-patterns)
- `destroy()`:
  - Disconnect all gain nodes
  - Close the AudioContext (check `audioCtx.state !== 'closed'` first to avoid errors)

Key constraints from research:
- `createMediaElementSource()` can only be called ONCE per video element. The mixer must be created once and stored in a ref. Guard with null check.
- Once `createMediaElementSource()` is called, the video element's audio is rerouted entirely through the Web Audio graph. The default HTML audio output is disconnected.
- Use `setTargetAtTime()` (not `linearRampToValueAtTime()` which requires a `setValueAtTime()` anchor) for smooth transitions.

**Modify handlePlay callback:**
Before the existing play promises logic, add lazy mixer creation:
```typescript
// Create audio mixer lazily on first play (user gesture satisfies autoplay policy)
if (!audioMixerRef.current) {
  const videoEls = videoRefs.current.filter(
    (v): v is HTMLVideoElement => v !== null,
  );
  if (videoEls.length > 0) {
    audioMixerRef.current = createAudioMixer(videoEls);
    audioMixerRef.current.setMode(audioMode);
  }
}
```

IMPORTANT: The mixer MUST be created inside the play handler (a user gesture), not in a useEffect. This satisfies browser AudioContext autoplay policy AND avoids React StrictMode double-fire issues with `createMediaElementSource()`.

Add `audioMode` to handlePlay's dependency array since it reads the current mode on mixer creation.

**Add audio mode change handler:**
