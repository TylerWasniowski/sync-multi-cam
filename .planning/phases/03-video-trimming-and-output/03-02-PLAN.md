**Step 1: Create src/components/PipelineProgress.tsx**

Create a new file `src/components/PipelineProgress.tsx` that is a stage-agnostic replacement for `SyncProgress.tsx`. This is a REFACTOR — not a bolt-on. The new component drives progress display for ALL pipeline stages using the `PipelineProgress` type from `src/types/index.ts`.

```typescript
import type { PipelineProgress as PipelineProgressType } from '../types/index.ts';

interface PipelineProgressProps {
  progress: PipelineProgressType;
}

export function PipelineProgress({ progress }: PipelineProgressProps) {
  if (progress.stage === 'idle') return null;

  const stageLabels: Record<string, string> = {
    extracting: 'Extracting Audio',
    correlating: 'Analyzing Sync',
    trimming: 'Trimming Videos',
    zipping: 'Building Download',
    complete: 'Complete',
    error: 'Failed',
  };

  const percentage = progress.total > 0
    ? Math.round((progress.current / progress.total) * 100)
    : 0;

  return (
    <div className="bg-gray-900 border border-gray-800 rounded-lg p-4">
      <div className="flex items-center justify-between mb-2">
        <span className="text-sm font-medium text-gray-300">
          {stageLabels[progress.stage] || progress.stage}
        </span>
        <span className="text-sm text-gray-500">
          {progress.current}/{progress.total}
        </span>
      </div>
      <div className="w-full bg-gray-800 rounded-full h-2">
        <div
          className={`h-2 rounded-full transition-all duration-300 ${
            progress.stage === 'error' ? 'bg-red-500' :
            progress.stage === 'complete' ? 'bg-green-500' :
            'bg-blue-500'
          }`}
          style={{ width: `${percentage}%` }}
        />
      </div>
      <p className="text-xs text-gray-500 mt-2">{progress.message}</p>
    </div>
  );
}
```

This is essentially the same visual component as SyncProgress but with the extended stage labels and using `PipelineProgress`/`PipelineStage` types instead of `SyncProgress`/`SyncStage`.

// Calculate trim amounts: align all files to the latest-starting track
const maxOffset = Math.max(...results.map(r => r.offsetSeconds));

Then the full pipeline extension after correlation:

```
Phase 3: Trim videos sequentially
- Set progress to stage 'trimming', total = files.length
- For each file (using trimAmounts):
  - Update progress: current = i+1, message = "Trimming {fileName}..."
  - Look up the VideoFile from the files array by fileId
  - Call trimVideo(videoFile.file, trimSeconds, onProgress)
  - The onProgress callback is optional here — updating message with file name is sufficient for v1
  - If trimSeconds === 0, trimVideo returns null (skipped)
  - For skipped files (reference/latest), use the original File blob for download later
  - Store the result: { fileId, fileName, trimmedData, trimSeconds, originalFile }
- Build DownloadableResult[] by merging SyncResult data with trim data

Phase 4: Build ZIP
- Set progress to stage 'zipping', current = 0, total = 1, message = "Creating ZIP archive..."
- Collect all files for zip: for each result, if trimmedData exists use it, if skipped read original file as Uint8Array
- For skipped files: read the original File as ArrayBuffer via file.arrayBuffer(), then new Uint8Array(buffer)
- File naming: "synced_{originalName}" for trimmed files, original name for skipped files
- Call buildZip(trimmedFiles) to get zipData Uint8Array
- Set zipData state
- Update progress: current = 1, message = "ZIP ready"

Phase 5: Auto-download ZIP and set complete
- Call triggerDownload(zipData, 'synced_videos.zip', 'application/zip')
- Set progress to stage 'complete', current = files.length, total = files.length, message = "Pipeline complete — {N} files synced and ready for download"
```

Error handling:
- Wrap the entire post-correlation pipeline in its own try/catch nested inside the existing try/catch
- If trimming/zipping fails, set progress to 'error' stage with the error message
- Individual file trim failures: if a single trimVideo() throws, catch it, log a warning, mark that file as failed in results (set trimmedData = null, add an error flag), but continue with remaining files
- If ALL files fail trimming, set pipeline to error state
