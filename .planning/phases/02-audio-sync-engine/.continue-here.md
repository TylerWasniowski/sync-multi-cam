**Bug investigation (uncommitted):**
- Discovered `syncWorkerConcurrent()` has a thread-splitting bug at 4+ threads
  - Proven in Node.js: `sync()` and `syncWorker()` give correct results, `syncWorkerConcurrent(4+)` gives wrong offset
  - Root cause: thread chunking splits base audio into pieces smaller than comparison, algorithm can't find match in any chunk
- Switched audioSync.ts from `syncWorkerConcurrent` to `syncWorker`
- Removed `shared: true` option (not needed for syncWorker)
- Updated tests to match (all 22 still pass)
- Added robust WAV header parsing (finds 'data' chunk instead of assuming 44 bytes)
- Added debug console.log in audioExtractor.ts and audioSync.ts
