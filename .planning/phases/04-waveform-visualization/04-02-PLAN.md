  <name>Task 1: Build WaveformTrack and WaveformPanel with linked interaction</name>
  <files>src/components/WaveformTrack.tsx, src/components/WaveformPanel.tsx</files>
  <action>
    **WaveformTrack.tsx** -- A single row containing a filename label and WaveformCanvas. Handles pointer/wheel/touch events and forwards them to the parent via callbacks.

    Props:
    ```typescript
    interface WaveformTrackProps {
      fileName: string;
      isReference: boolean;
      peaks: MultiResolutionPeaks;
      syncResult: { offsetSeconds: number; confidence: number };
      viewState: ViewState;
      onViewStateChange: (update: Partial<ViewState>) => void;
      onPointerEnter: () => void;
      onPointerLeave: () => void;
    }
    ```

    Implementation:
    1. Use a container div with `useRef` to measure its width via `ResizeObserver` (store in local state). This drives the `width` prop to WaveformCanvas.
    2. Call `selectPeakLevel(peaks, viewState.samplesPerPixel, containerWidth)` to pick the right resolution for current zoom.
    3. Render: filename label (left, ~160px, truncated) + WaveformCanvas (fills remaining width). Track height: 80px. Use flex layout.
    4. Show offset label: "+X.XXs" or "REF" badge next to filename. Show confidence as small text.
    5. Attach event handlers to the canvas container div:
       - `onWheel`: If `e.ctrlKey || e.metaKey`, preventDefault and compute zoom. Zoom factor = `e.deltaY > 0 ? 1.1 : 0.9`. New samplesPerPixel = clamp(current * factor, MIN_SPP, MAX_SPP). Keep cursor position stable: calculate cursorSample from e.offsetX, recompute scrollOffset so that sample stays at same pixel. Call `onViewStateChange({ samplesPerPixel: newSPP, scrollOffset: newOffset })`.
       - If NOT ctrlKey/metaKey on wheel, let event propagate naturally (page scrolls).
       - `onPointerDown` (button 0 only): Start drag. Store startX and startScrollOffset in refs. Set `pointer-capture` on the element. Add pointermove/pointerup listeners.
       - `onPointerMove` during drag: Compute delta pixels, convert to delta samples (`deltaX * samplesPerPixel`), update scrollOffset. Gate via requestAnimationFrame ref.
       - `onPointerUp`: Release pointer capture, commit final scrollOffset to state.
       - `onPointerMove` (not dragging): Convert e.offsetX to time: `(viewState.scrollOffset + e.offsetX * viewState.samplesPerPixel) / peaks.sampleRate`. Call `onViewStateChange({ cursorTime: time })`.
       - `onPointerEnter/Leave`: Forward to parent for cursor visibility management.
    6. **Touchscreen two-finger pinch-to-zoom and swipe (per user decision "Touch: pinch-to-zoom + swipe"):**
       - Add `touch-action: none` CSS on the canvas container div to prevent browser default pan/zoom and let us handle all touch gestures.
       - `onTouchStart`: Store active touches in a ref (array of `{ id, clientX, clientY }`). If exactly 2 touches, compute initial pinch distance = `Math.hypot(t1.clientX - t2.clientX, t1.clientY - t2.clientY)` and store as `pinchStartDistance`. Also store the midpoint X of the two touches for zoom-anchor calculation. Set a `isPinching` ref to true.
       - `onTouchMove`: If `isPinching` and 2 active touches: compute new distance between the two touch points. Zoom ratio = `newDistance / pinchStartDistance`. New samplesPerPixel = clamp(startSPP / zoomRatio, MIN_SPP, MAX_SPP). Anchor zoom at the midpoint X of the two touches (convert midpoint to sample position, recompute scrollOffset so that sample stays at midpoint pixel). Call `onViewStateChange({ samplesPerPixel: newSPP, scrollOffset: newOffset })`. Update `pinchStartDistance = newDistance` and `startSPP = newSPP` for continuous tracking.
       - If only 1 active touch and NOT `isPinching`: treat as swipe/pan. Compute deltaX from last touch position, convert to delta samples, update scrollOffset (same logic as pointer drag). Gate via rAF.
       - `onTouchEnd` / `onTouchCancel`: Remove ended touch from active touches ref. If fewer than 2 touches remain, set `isPinching = false`. If 0 touches remain, commit final scrollOffset.
       - Use `e.preventDefault()` in touchmove handler to suppress scroll.
    7. Constants: `MIN_SAMPLES_PER_PIXEL = 1` (max zoom), `MAX_SAMPLES_PER_PIXEL` = computed from duration to fit entire track in ~200px (min zoom).
    8. Use `cursor-grab` when not dragging, `cursor-grabbing` during drag (via local isDragging ref).

    **WaveformPanel.tsx** -- Container that renders all WaveformTracks with shared ViewState.

    Props:
    ```typescript
    interface WaveformPanelProps {
      peaksMap: Map<string, MultiResolutionPeaks>;  // fileId -> peaks
      results: DownloadableResult[];
    }
    ```

    Implementation:
    1. State: `const [viewState, setViewState] = useState<ViewState>` initialized with default zoom (fit longest track in panel width). Use a ref + ResizeObserver on the panel container to get panel width. Default samplesPerPixel = `maxDuration * sampleRate / panelWidth`.
    2. `handleViewStateChange` callback: merges partial ViewState updates. Clamp scrollOffset to [0, maxScrollOffset] where maxScrollOffset = maxTotalSamples - canvasWidth * samplesPerPixel. Use requestAnimationFrame gating: store pending update in a ref, schedule rAF, apply in the rAF callback to coalesce rapid events.
    3. When cursor leaves all tracks, set cursorTime to null.
    4. Render: A dark card container (bg-gray-900, border-gray-800, rounded-lg) matching existing app card style. Header: "Audio Waveforms" with a subtitle showing zoom level (e.g., "2.5x zoom"). Vertically stack one WaveformTrack per result, in the same order as results. Dividers between tracks (divide-y divide-gray-800).
    5. Handle edge case: if peaksMap is empty, render nothing.
    6. Memoize the track list with useMemo to avoid re-creating on every viewState change (viewState changes should only trigger canvas redraws, not React re-renders of the track list).

    Integrate waveform visualization into the existing pipeline and UI.

    1. **Add state for peaks in App.tsx:**
       ```typescript
       const [waveformPeaks, setWaveformPeaks] = useState<Map<string, MultiResolutionPeaks>>(new Map());
       ```
       Import `MultiResolutionPeaks` from types and `computeMultiResolutionPeaks` from `waveformPeaks.ts`.

    2. **Compute peaks during extraction phase in handleSync:**
       After each `extractAudio(files[i].file)` call, immediately compute multi-resolution peaks from the extracted audio data, then let the raw Float32Array proceed to audioTracks for correlation as before. Add to the extraction loop:
       ```typescript
       const audio = await extractAudio(files[i].file);
       // Compute waveform peaks while we have the raw audio data
       const peaks = computeMultiResolutionPeaks(audio.channelData[0], audio.sampleRate);
       setWaveformPeaks(prev => new Map(prev).set(files[i].id, peaks));
       audioTracks.push({ fileId: files[i].id, fileName: files[i].name, audio });
       ```
       This way peaks are computed immediately after extraction (when Float32Array is in memory), before it gets passed to correlation. The raw Float32Array can be GC'd after correlation completes.

    3. **Reset peaks on new pipeline run:** At the top of handleSync (where other state is reset), add:
       ```typescript
       setWaveformPeaks(new Map());
       ```

    4. **Render WaveformPanel below SyncResults in the JSX:**
       ```tsx
       {syncResults.length > 0 && waveformPeaks.size > 0 && (
         <div className="mt-6">
           <WaveformPanel peaksMap={waveformPeaks} results={syncResults} />
         </div>
       )}
       ```
       Import WaveformPanel at the top of App.tsx.

    5. **No changes to the pipeline logic itself** -- extraction, correlation, trimming, and zipping all remain the same. Peaks are computed as a side effect during extraction, not blocking the pipeline.
