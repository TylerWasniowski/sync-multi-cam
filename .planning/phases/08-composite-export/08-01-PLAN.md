<objective>
Build and test the pure filtergraph builder that converts grid tile positions + resolution + audio config into a complete FFmpeg args array. This is the most complex and error-prone part of the export pipeline -- it MUST be unit tested before integration.

Purpose: The xstack filter_complex string generation is the heart of composite export. Isolating it as a pure function enables thorough testing of edge cases (odd dimensions, incomplete rows, mixed audio) without needing FFmpeg WASM.

Output: Tested `buildExportArgs()` function, resolution presets, audio arg builder, and ExportState type.
</objective>

  <files>src/lib/exportComposite.ts, src/lib/exportComposite.test.ts</files>
  <behavior>
    - buildFilterComplex(tiles, inputCount) returns a semicolon-separated string with scale filters + xstack
    - Each scale filter rounds tile dimensions to even numbers using bitwise AND ~1
    - Each scale filter sets setsar=1 after scale
    - xstack layout string uses tile x_y positions joined by |
    - xstack includes fill=black and correct input count
    - buildAudioArgs('single', trackIndex=2, 4) returns { filterParts: [], mapArgs: ['-map', '2:a'] }
    - buildAudioArgs('mix', [0,1,3], 4) returns amix filter with inputs=3, normalize=0, duration=longest, and mapArgs ['-map', '[aout]']
    - buildAudioArgs('mix', [], 4) returns { filterParts: [], mapArgs: ['-an'] } (no audio)
    - buildAudioArgs('mix', [2], 4) returns single map (optimization: 1 track = no amix needed)
    - buildAudioArgs('none') returns { filterParts: [], mapArgs: ['-an'] }
    - buildExportArgs assembles full args array: -i flags, -filter_complex, -map [vout], audio args, -c:v libx264, -preset fast, -crf, -r, -pix_fmt yuv420p, -movflags +faststart, output.mp4
    - For 4 cameras at 1080p: produces 4 -i pairs, 4 scale filters, 1 xstack filter, correct layout string
    - For 3 cameras at 720p (incomplete last row): xstack positions match computeGridLayout output with centered last row
    - For 1 camera: single scale + trivial xstack with 1 input
    - Odd tile dimensions (e.g., 641x361) are rounded down to even (640x360)
  </behavior>
